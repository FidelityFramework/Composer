# Parallel zipper research: historical record

Original investigation: January 27, 2026. Status corrected September 25, 2026:
**research leads retained; implementation recommendations superseded**.

The investigation compared Nanopass, MLIR/Triton and Chez Scheme while considering
function-level work in Alex. It did not demonstrate a Composer parallel backend.
Its estimates of 1.5–2× speedups, short implementation timelines and universal
claims about production compiler scheduling were not measured evidence for Alex
and are withdrawn.

Current authority is the [Alex architecture](Alex_Architecture_Overview.md),
[interactive compiler workbench](Interactive_Compiler_Workbench.md) and
[incremental contract](Nanopass_Incremental_Contract_Direction.md).

## Research questions and retained examples

### Nanopass recursive transformations

The original study used this schematic Nanopass example:

```scheme
(define-pass remove-one-armed-if : Lsrc (e) -> L1 ()
  (Expr : Expr (e) -> Expr ()
    [(if ,[e0] ,[e1]) '(if ,e0 ,e1 (void))]
    ...autogenerated clauses...))
```

The catamorphism syntax motivates studying recursive transformation and result
binding. It does not establish a Huet zipper with retained focus/path context.
The earlier assertion that every nanopass is a zipper is withdrawn. A dependent
composition such as `(pass3 (pass2 (pass1 input)))` orders those dependencies; it
does not prove a universal absence of parallelism inside or between other work.

Research leads: Sarkar, Waddell and Dybvig's Nanopass papers (ICFP 2004 and 2013),
Keep's dissertation (2013), and the local `nanopass-framework-scheme` checkout.
The former unattributed Chez performance numbers and inconsistent pass counts
are not retained as verified measurements.

### MLIR and Triton scheduling

The study examined pass-manager construction and dialect declarations:

```text
construct pass manager for a context
add transformation passes
run the pipeline on an operation
```

These are useful places to investigate operation isolation and scheduling. A
list of `dependentDialects` is not proof of semantic independence or a complete
pass-order contract. General claims that operation locks make arbitrary
mutation safe, or that all production compilers use one parallelization model,
are withdrawn. The local `triton-cpu` checkout remains a research lead; any new
implementation must cite and validate the specific mechanism it adopts.

### Zipper and graph traversal

The original references remain relevant to positional observation:

- Huet (1997), *The Zipper*.
- Ramsey and Dias (2006), *An Applicative Control-Flow Graph Based on Huet's Zipper*.
- McBride (2001), *The Derivative of a Regular Type is its Type of One-Hole Contexts*.

They do not establish that partitioning Alex by function preserves scope,
occurrence, effects, residence or proof provenance.

## Corrected conclusions for Alex

Immutable graph reads can be a starting point for concurrency research. They do
not imply thread-safe lazy observations, isolated emission bookkeeping or a
reentrant compiler. Current process-global state requires serialization or
worker isolation in the proposed workbench.

The prior design's accumulator union is not an approved partition contract.
Associativity changes grouping; commutativity changes order. Appending lists is
associative but order-sensitive. Map merge requires a collision policy. Effects,
initialization, shared symbols and obligation correspondence need their own
preservation evidence before worker results can be combined.

A valid experiment would preserve Baker construction and Alex ctx pull
witnessing, compare a named admitted slice against fresh ordinary compilation,
and measure compilation, scheduling, merge and memory costs. Equal generated
text alone does not establish the required semantic preservation. No function
count, throughput gain or latency target is established here.
